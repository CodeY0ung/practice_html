About Me

안정적인 금융 시스템을 만드는 개발자

실제 사용되는 서비스를 만드는 개발자가 되고 싶었습니다.

개발을 시작했을 때부터 제가 중요하게 생각했던 것은 단순히 코드를 작성하는 것이 아니라 실제 사용자가 사용하는 서비스를 만드는 것이었습니다.

대학 시절 스타트업의 초기 개발자로 참여하면서 요구사항을 정리하고 서비스를 직접 개발하여 배포하는 경험을 했습니다. 작은 서비스였지만 서버 장애와 운영 문제를 직접 경험하면서, 프로그램은 기능 구현이 끝나는 순간 완성되는 것이 아니라 안정적으로 운영될 때 비로소 가치가 있다는 것을 배웠습니다.

금융 시스템에서 안정성의 의미를 배웠습니다.

부산은행에 입행한 이후에는 금융 서비스의 백엔드 개발과 운영 업무를 경험했습니다.

금융 시스템에서는 작은 오류도 고객의 자산과 서비스 신뢰도에 직접적인 영향을 줄 수 있습니다. 그래서 기능을 빠르게 구현하는 것보다 거래 데이터가 정확하게 처리되는지, 실패 상황에서 데이터가 안전하게 복구되는지, 장애 발생 시 원인을 추적할 수 있는지를 중요하게 생각하게 되었습니다.

이를 통해 트랜잭션 관리, 예외 처리, 테스트, 로그와 모니터링이 단순한 개발 기법이 아니라 서비스의 신뢰성을 만드는 핵심 요소라는 것을 배웠습니다.

장애를 해결하는 것보다 다시 발생하지 않도록 만드는 것을 중요하게 생각합니다.

운영 업무를 경험하면서 개발자가 장애를 완전히 피할 수는 없다는 것을 알게 되었습니다.

중요한 것은 장애가 발생했을 때 빠르게 복구하는 것뿐만 아니라, 로그와 데이터를 통해 원인을 찾고 같은 문제가 다시 발생하지 않도록 시스템을 개선하는 것입니다.

문제가 발생하면 애플리케이션 코드뿐만 아니라 데이터베이스 쿼리, 네트워크, 서버 자원, 외부 시스템 연계까지 범위를 넓혀 원인을 분석하려고 합니다.

유지보수하기 쉬운 코드를 만들기 위해 노력합니다.

실무에서는 새로운 기능을 만드는 시간보다 기존 코드를 이해하고 수정하는 시간이 더 많았습니다.

그래서 코드를 작성할 때 현재 요구사항을 해결하는 것만으로 끝내지 않고, 이후 새로운 개발자가 코드를 읽었을 때 이해할 수 있는지, 요구사항 변경 시 수정 범위를 최소화할 수 있는지, 테스트를 통해 변경의 안전성을 확인할 수 있는지를 함께 고민합니다.

테스트 가능한 구조와 명확한 책임 분리, 이해하기 쉬운 코드는 장기적으로 개발 속도를 높이는 가장 중요한 요소라고 생각합니다.

금융 도메인을 이해하는 백엔드 개발자로 성장하고 있습니다.

앞으로의 목표는 단순히 Java와 Spring을 잘 사용하는 개발자가 아니라 금융 서비스의 구조와 업무를 이해하고, 기술적인 판단까지 할 수 있는 백엔드 개발자로 성장하는 것입니다.

대규모 트래픽 처리, 금융 데이터 정합성, 분산 시스템, 장애 대응 및 시스템 아키텍처에 대한 경험을 계속 쌓으며 중요한 금융 서비스를 설계하고 운영할 수 있는 개발자가 되고자 합니다.
